## Command overview

`beacon rules pull` downloads a rule file or rule pack from an explicit URL and installs valid rules into the local store.

```bash title="Command syntax"
beacon rules pull <url> [flags]
```

This is the only `beacon rules` command that reaches the network, and only when you run it. Beacon never fetches rules on its own. The full Beacon threat-rule pack is published as a versioned `threat-rules.tar.gz` asset on each Agent Beacon GitHub release.

## Supported inputs

`beacon rules pull` accepts:

| Input | Description |
|-------|-------------|
| `.rule.yaml` | One rule file |
| `.tar.gz` | Gzipped tarball containing `.rule.yaml` files |
| `.tgz` | Gzipped tarball containing `.rule.yaml` files |

Downloaded tarballs only install `.rule.yaml` entries. Archive entries containing path traversal elements are rejected before install.

## Transport and integrity

Rules decide what `beacon scan` can see, so a pull refuses sources that a network attacker could tamper with:

- The URL must use `https://`. Plain `http://` is accepted only for a loopback host (`localhost`, `127.0.0.1`, `::1`), for testing a pack served from your own machine.
- Redirects are followed only while they stay on `https://` (for example, a GitHub release download redirecting to its storage host). A redirect from `https://` to `http://`, or to a host the command would not have accepted directly, stops the pull.
- With `--sha256 <hex>`, Beacon hashes the downloaded bytes and installs nothing unless they match. Use the SHA-256 digest the publisher lists for the asset; GitHub shows one for every release asset. Without `--sha256`, Beacon prints the digest of what it downloaded so you can compare it yourself.

The whole download is read and checked before anything is unpacked or written to the store, and these limits apply:

| Limit | Value |
|-------|-------|
| Download size | 32 MiB |
| Tarball entries (every entry, rule or not) | 10,000 |
| Tarball size once decompressed | 64 MiB |
| One `.rule.yaml` file | 1 MiB |

The published rule pack is about 50 KB compressed, with under 100 entries and about 300 KB decompressed. A source over any limit fails with an error that names the limit, and nothing is installed.

Installing rules never switches off the [built-in baseline](/cli/rules-list): a pulled rule replaces a baseline rule only when it has the same id.

## Examples

Pull a rule pack:

```bash title="Pull a rule pack"
beacon rules pull https://github.com/asymptote-labs/agent-beacon/releases/download/v0.0.95/threat-rules.tar.gz
```

Pull a rule pack and verify it against the asset's published SHA-256 digest:

```bash title="Pull and verify a rule pack"
beacon rules pull https://github.com/asymptote-labs/agent-beacon/releases/download/v0.0.95/threat-rules.tar.gz \
  --sha256 <sha256-of-threat-rules.tar.gz>
```

Pull one rule file:

```bash title="Pull one rule file"
beacon rules pull https://example.com/rules/suspicious-egress-command.rule.yaml
```

Overwrite an existing rule with the same id:

```bash title="Overwrite existing rules"
beacon rules pull https://github.com/asymptote-labs/agent-beacon/releases/download/v0.0.95/threat-rules.tar.gz --force
```

Install into the system-mode rule store:

```bash title="Pull system-mode rules"
sudo beacon rules pull https://github.com/asymptote-labs/agent-beacon/releases/download/v0.0.95/threat-rules.tar.gz --system
```

## Flags

| Flag | Description |
|------|-------------|
| `--user` | Use per-user endpoint paths. Enabled by default |
| `--system` | Use system endpoint paths |
| `--force` | Overwrite an existing rule with the same id |
| `--sha256 <hex>` | Expected SHA-256 of the downloaded file, as 64 hex digits (a `sha256:` prefix is accepted). Nothing is installed on a mismatch |
