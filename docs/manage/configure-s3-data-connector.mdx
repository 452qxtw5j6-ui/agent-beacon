## Overview

Beacon can ingest customer-hosted event files from a private AWS S3 bucket or prefix. Beacon reads them with the access key of a read-only IAM user you create. That user can list the bucket, read objects below the prefix you choose, and consume two notification queues, and nothing else.

Beacon can't assume an IAM role in your account for this connector, so use an IAM user's access key.

Do not make the bucket public. Do not grant write or delete permissions.

## Create the read-only user and queues

Beacon reads the bucket with the access key of a read-only IAM user. It also needs two SQS queues, one per stream, that S3 notifies of every new object. Beacon loads the objects the queues name, in any order. Without them Beacon would read objects in name order and could skip ones that arrive late, which happens when many Macs upload at once.

Use a bucket dedicated to Beacon telemetry: the notification setup below replaces any notifications already configured on the bucket.

<Tabs>
  <Tab title="Terraform">
    If you created the bucket with [AWS S3 with Terraform](/log-forwarding/aws-s3-terraform), turn on the reader in the module block and apply:

    ```hcl
    module "beacon_s3" {
      # ...your existing settings...
      create_beacon_reader = true
    }
    ```

    The module creates `beacon-s3-reader` with the policy shown in the other tab, including `kms:Decrypt` when you set `kms_key_arn`, the two queues with their dead-letter queues, and the bucket notification. Create the reader's access key:

    ```bash
    aws iam create-access-key --user-name beacon-s3-reader --output json
    ```

    The `beacon_reader_queue_urls` output holds the two queue URLs.
  </Tab>
  <Tab title="AWS CLI">
    **Set your values.** Use the bucket's region and the prefix that holds the event files:

    ```bash
    export AWS_REGION="<bucket region>"
    export BEACON_S3_BUCKET="<bucket>"
    export BEACON_S3_PREFIX="beacon-prod"
    export AWS_ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
    ```

    **Create the queues.** Each stream gets a queue that only this bucket may send to, and a dead-letter queue that keeps a message after ten failed deliveries:

    ```bash
    for stream in runtime inventory; do
      dlq_url="$(aws sqs create-queue --region "$AWS_REGION" \
        --queue-name "beacon-s3-reader-${stream}-dlq" \
        --attributes MessageRetentionPeriod=1209600,SqsManagedSseEnabled=true \
        --query QueueUrl --output text)"
      dlq_arn="$(aws sqs get-queue-attributes --region "$AWS_REGION" --queue-url "$dlq_url" \
        --attribute-names QueueArn --query Attributes.QueueArn --output text)"
      queue_arn="arn:aws:sqs:${AWS_REGION}:${AWS_ACCOUNT_ID}:beacon-s3-reader-${stream}"
      cat > "beacon-s3-reader-${stream}.json" <<EOF
    {
      "MessageRetentionPeriod": "1209600",
      "VisibilityTimeout": "300",
      "SqsManagedSseEnabled": "true",
      "RedrivePolicy": "{\"deadLetterTargetArn\":\"${dlq_arn}\",\"maxReceiveCount\":10}",
      "Policy": "{\"Version\":\"2012-10-17\",\"Statement\":[{\"Effect\":\"Allow\",\"Principal\":{\"Service\":\"s3.amazonaws.com\"},\"Action\":\"sqs:SendMessage\",\"Resource\":\"${queue_arn}\",\"Condition\":{\"ArnEquals\":{\"aws:SourceArn\":\"arn:aws:s3:::${BEACON_S3_BUCKET}\"},\"StringEquals\":{\"aws:SourceAccount\":\"${AWS_ACCOUNT_ID}\"}}}]}"
    }
    EOF
      aws sqs create-queue --region "$AWS_REGION" \
        --queue-name "beacon-s3-reader-${stream}" \
        --attributes "file://beacon-s3-reader-${stream}.json"
    done
    ```

    The loop prints the `QueueUrl` of the `runtime` and `inventory` queues. Keep both to send to Beacon.

    **Send new-object notifications to the queues:**

    ```bash
    cat > beacon-notifications.json <<EOF
    {
      "QueueConfigurations": [
        {
          "Id": "beacon-runtime",
          "QueueArn": "arn:aws:sqs:${AWS_REGION}:${AWS_ACCOUNT_ID}:beacon-s3-reader-runtime",
          "Events": ["s3:ObjectCreated:*"],
          "Filter": {"Key": {"FilterRules": [{"Name": "prefix", "Value": "${BEACON_S3_PREFIX}/runtime/"}]}}
        },
        {
          "Id": "beacon-inventory",
          "QueueArn": "arn:aws:sqs:${AWS_REGION}:${AWS_ACCOUNT_ID}:beacon-s3-reader-inventory",
          "Events": ["s3:ObjectCreated:*"],
          "Filter": {"Key": {"FilterRules": [{"Name": "prefix", "Value": "${BEACON_S3_PREFIX}/inventory/"}]}}
        }
      ]
    }
    EOF
    aws s3api put-bucket-notification-configuration \
      --bucket "$BEACON_S3_BUCKET" \
      --notification-configuration file://beacon-notifications.json
    ```

    It prints nothing when it works.

    **Create the user** and give it read-only access to the prefix and the two queues:

    ```bash
    aws iam create-user --user-name beacon-s3-reader

    aws iam put-user-policy \
      --user-name beacon-s3-reader \
      --policy-name BeaconTelemetryReadOnly \
      --policy-document "$(cat <<EOF
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": ["s3:ListBucket", "s3:GetBucketLocation"],
          "Resource": "arn:aws:s3:::${BEACON_S3_BUCKET}"
        },
        {
          "Effect": "Allow",
          "Action": "s3:GetObject",
          "Resource": "arn:aws:s3:::${BEACON_S3_BUCKET}/${BEACON_S3_PREFIX}/*"
        },
        {
          "Effect": "Allow",
          "Action": ["sqs:ReceiveMessage", "sqs:DeleteMessage", "sqs:GetQueueAttributes"],
          "Resource": [
            "arn:aws:sqs:${AWS_REGION}:${AWS_ACCOUNT_ID}:beacon-s3-reader-runtime",
            "arn:aws:sqs:${AWS_REGION}:${AWS_ACCOUNT_ID}:beacon-s3-reader-inventory"
          ]
        },
        {
          "Effect": "Allow",
          "Action": "sqs:ListQueues",
          "Resource": "*"
        }
      ]
    }
    EOF
    )"
    ```

    If the bucket uses SSE-KMS, also allow `kms:Decrypt` on the key, and make sure the key policy lets IAM policies in your account grant it:

    ```json title="SSE-KMS decrypt statement"
    {
      "Effect": "Allow",
      "Action": "kms:Decrypt",
      "Resource": "YOUR_KMS_KEY_ARN"
    }
    ```

    **Create the access key:**

    ```bash
    aws iam create-access-key --user-name beacon-s3-reader --output json
    ```
  </Tab>
</Tabs>

AWS shows the secret only once. Keep it in your password manager until you send it to Beacon.

## Send Beacon the details

Send these through the secure channel your Beacon contact gives you. Don't send the secret access key by email or chat.

- S3 bucket name and AWS region
- Prefix for the event files, such as `s3://your-bucket/beacon-prod/`
- The two queue URLs, for `runtime` and `inventory`
- The access key ID and secret access key
- KMS key ARN, only if SSE-KMS is enabled
- For files that Beacon's forwarder didn't write: the file format (ideally JSONL), delivery cadence, approximate event volume, and a small sample file or example JSONL row

To rotate the key later, create a second key for `beacon-s3-reader`, send it to Beacon, and delete the old key once Beacon confirms the switch.

## Using Google Cloud Storage

For a Cloud Storage bucket, no key is involved. Beacon reads with its own service account, `beacon-clickpipes-reader@asymptote-labs.iam.gserviceaccount.com`, and needs a Pub/Sub subscription per stream for the same reason S3 needs the queues.

<Tabs>
  <Tab title="Terraform">
    Set `grant_beacon_read_access = true` in the [Terraform module](/log-forwarding/gcs-terraform) and apply. Send Beacon the bucket name, the prefix, and the two subscriptions in `beacon_reader_subscriptions`.
  </Tab>
  <Tab title="gcloud">
    ```bash
    export GCP_PROJECT="<project-id>"
    export BEACON_GCS_BUCKET="<bucket>"
    export BEACON_GCS_PREFIX="beacon-prod"
    export BEACON_READER="serviceAccount:beacon-clickpipes-reader@asymptote-labs.iam.gserviceaccount.com"
    export BEACON_TOPIC="beacon-${BEACON_GCS_BUCKET}-objects"

    # Let Beacon read the bucket.
    gcloud storage buckets add-iam-policy-binding "gs://${BEACON_GCS_BUCKET}" \
      --member "$BEACON_READER" --role roles/storage.objectViewer

    # Publish every new object below the prefix to a topic.
    gcloud pubsub topics create "$BEACON_TOPIC" --project "$GCP_PROJECT"
    gcloud pubsub topics add-iam-policy-binding "$BEACON_TOPIC" --project "$GCP_PROJECT" \
      --member "serviceAccount:$(gcloud storage service-agent --project "$GCP_PROJECT" | tr -d '[:space:]')" \
      --role roles/pubsub.publisher
    gcloud storage buckets notifications create "gs://${BEACON_GCS_BUCKET}" \
      --topic "projects/${GCP_PROJECT}/topics/${BEACON_TOPIC}" \
      --event-types OBJECT_FINALIZE \
      --object-prefix "${BEACON_GCS_PREFIX}/" \
      --payload-format json

    # One subscription per stream that Beacon may consume. They never expire.
    for stream in runtime inventory; do
      gcloud pubsub subscriptions create "beacon-${BEACON_GCS_BUCKET}-${stream}" \
        --project "$GCP_PROJECT" \
        --topic "$BEACON_TOPIC" \
        --message-filter "attributes.eventType = \"OBJECT_FINALIZE\" AND hasPrefix(attributes.objectId, \"${BEACON_GCS_PREFIX}/${stream}/\")" \
        --ack-deadline 60 \
        --message-retention-duration 7d \
        --expiration-period never
      for role in roles/pubsub.subscriber roles/pubsub.viewer; do
        gcloud pubsub subscriptions add-iam-policy-binding "beacon-${BEACON_GCS_BUCKET}-${stream}" \
          --project "$GCP_PROJECT" --member "$BEACON_READER" --role "$role"
      done
    done
    ```

    Send Beacon the bucket name, the prefix, and the two subscriptions: `projects/<project-id>/subscriptions/beacon-<bucket>-runtime` and `-inventory`.
  </Tab>
</Tabs>

## Event file requirements

Use newline-delimited JSON, with one complete JSON object per line. Each event should include a UTC-compatible timestamp and stable fields for user, host, repository, branch, agent runtime, event action, and event category when available.

Share a representative sample file before production ingestion. The sample should show realistic field names and value shapes, but should not include secrets.

Beacon's own S3 forwarder already writes this format, as gzip-compressed JSONL below `<prefix>/runtime/` and `<prefix>/inventory/`.
