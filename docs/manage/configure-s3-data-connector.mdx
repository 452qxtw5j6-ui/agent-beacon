## Overview

Beacon can ingest customer-hosted event files from a private AWS S3 bucket or prefix. Beacon reads them with the access key of a read-only IAM user you create. That user can list the bucket and read objects below the prefix you choose, and nothing else.

Beacon can't assume an IAM role in your account for this connector, so use an IAM user's access key.

Do not make the bucket public. Do not grant write or delete permissions.

## Create the read-only user

<Tabs>
  <Tab title="Terraform">
    If you created the bucket with [AWS S3 with Terraform](/log-forwarding/aws-s3-terraform), turn on the reader in the module block and apply:

    ```hcl
    module "beacon_s3" {
      # ...your existing settings...
      create_beacon_reader = true
    }
    ```

    The module creates `beacon-s3-reader` with the policy shown in the other tab, including `kms:Decrypt` when you set `kms_key_arn`. Create its access key:

    ```bash
    aws iam create-access-key --user-name beacon-s3-reader --output json
    ```
  </Tab>
  <Tab title="AWS CLI">
    Set the bucket and the prefix that holds the event files:

    ```bash
    export BEACON_S3_BUCKET="<bucket>"
    export BEACON_S3_PREFIX="beacon-prod"
    ```

    Create the user and give it read-only access to that prefix:

    ```bash
    aws iam create-user --user-name beacon-s3-reader

    aws iam put-user-policy \
      --user-name beacon-s3-reader \
      --policy-name BeaconTelemetryReadOnly \
      --policy-document "$(cat <<EOF
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": ["s3:ListBucket", "s3:GetBucketLocation"],
          "Resource": "arn:aws:s3:::${BEACON_S3_BUCKET}"
        },
        {
          "Effect": "Allow",
          "Action": "s3:GetObject",
          "Resource": "arn:aws:s3:::${BEACON_S3_BUCKET}/${BEACON_S3_PREFIX}/*"
        }
      ]
    }
    EOF
    )"
    ```

    If the bucket uses SSE-KMS, also allow `kms:Decrypt` on the key, and make sure the key policy lets IAM policies in your account grant it:

    ```json title="SSE-KMS decrypt statement"
    {
      "Effect": "Allow",
      "Action": "kms:Decrypt",
      "Resource": "YOUR_KMS_KEY_ARN"
    }
    ```

    Create the access key:

    ```bash
    aws iam create-access-key --user-name beacon-s3-reader --output json
    ```
  </Tab>
</Tabs>

AWS shows the secret only once. Keep it in your password manager until you send it to Beacon.

## Send Beacon the details

Send these through the secure channel your Beacon contact gives you. Don't send the secret access key by email or chat.

- S3 bucket name and AWS region
- Prefix for the event files, such as `s3://your-bucket/beacon-prod/`
- The access key ID and secret access key
- KMS key ARN, only if SSE-KMS is enabled
- For files that Beacon's forwarder didn't write: the file format (ideally JSONL), delivery cadence, approximate event volume, and a small sample file or example JSONL row

To rotate the key later, create a second key for `beacon-s3-reader`, send it to Beacon, and delete the old key once Beacon confirms the switch.

## Using Google Cloud Storage

For a Cloud Storage bucket, no key is involved. Grant `roles/storage.objectViewer` on the bucket to `beacon-clickpipes-reader@asymptote-labs.iam.gserviceaccount.com`, or set `grant_beacon_read_access = true` in the [Terraform module](/log-forwarding/gcs-terraform). Then send Beacon the bucket name and prefix.

## Event file requirements

Use newline-delimited JSON, with one complete JSON object per line. Each event should include a UTC-compatible timestamp and stable fields for user, host, repository, branch, agent runtime, event action, and event category when available.

Share a representative sample file before production ingestion. The sample should show realistic field names and value shapes, but should not include secrets.

Beacon's own S3 forwarder already writes this format, as gzip-compressed JSONL below `<prefix>/runtime/` and `<prefix>/inventory/`.
